# 10. Звук

Файл `snd/snd.c`. Двести пятьдесят строк, которые заменяют OpenAL.

## Что такое цифровой звук

Звук — колебания давления воздуха. Микрофон измеряет его много раз в
секунду и записывает числа. 44100 измерений в секунду, каждое — 16-битное
число со знаком: -32768 самое тихое положение мембраны, +32767 самое
громкое.

Такая последовательность называется PCM. Ни `.wav`, ни звуковая карта не
делают с ней ничего умного: файл её хранит, карта отдаёт на динамик.

**Сэмпл** — одно число. **Кадр** (frame) — по одному сэмплу на каждый
канал: для стерео это два числа. **Чередование** (interleaved) — порядок
хранения: левый, правый, левый, правый.

Сложить два звука — сложить их числа. Сделать тише — умножить. На этом
построен весь микшер.

## Голос

```c
struct voice {
	const short *pcm;
	long frames;
	int channels;
	long step;         /* 16.16: сколько исходных кадров на выходной */
	long position;     /* 16.16: где мы сейчас */
	float gain;
	struct vec3 at;
	int spatial;
	int loop;
	int busy;
};

static struct voice voices[SND_VOICES];
```

Голос — это «проигрывается прямо сейчас». Массив на 32 штуки; тридцать
третий звук просто не начнётся, и `snd_Play` вернёт -1. Так лучше, чем
динамический список: ни выделений, ни неограниченного роста, а
одновременных звуков больше тридцати всё равно никто не различит.

`pcm` указывает **внутрь** файла (глава 08), а не в свою копию. Значит,
буфер с файлом должен жить, пока звук играет. Это цена отказа от
копирования, и её надо помнить.

## Частота: 16.16

Файл записан на 8000 Гц, устройство работает на 44100. Значит, на каждый
выходной кадр приходится 8000/44100 = 0.1814 исходного. Дробное число.

Хранить дробь в `float` можно, но накопленная ошибка со временем уведёт
позицию. Поэтому — фиксированная точка:

```c
	v->step = ((long)sound->rate << 16) / device_rate;
```

Число сдвигается на 16 бит влево, то есть умножается на 65536. Верхние
биты — целая часть, нижние 16 — дробная. Для 8000/44100 получается 11888,
то есть 0.1814 в этом представлении.

```c
		index = v->position >> 16;
		...
		v->position += v->step;
```

Позиция двигается сложением целых чисел, а номер сэмпла получается сдвигом
вправо на 16. Ни одного деления в цикле, ошибка не накапливается.

Такой пересчёт частоты называется nearest-neighbour: берётся ближайший
сэмпл без интерполяции. Слышно как лёгкая шершавость на сильно
растянутых звуках. Линейная интерполяция (взять два соседних и смешать)
добавляется четырьмя строками, если понадобится.

## Расстояние и панорама

```c
static void
levels(const struct voice *v, float *left, float *right)
{
	delta = v3_sub(v->at, ear_pos);
	distance = v3_len(delta);

	if (distance >= range_max) {
		*left = 0.0f;
		*right = 0.0f;
		return;
	}
	if (distance <= range_ref)
		attenuation = 1.0f;
	else
		attenuation = range_ref / distance;
```

Две настройки вместо модели затухания: до `range_ref` метров громкость
полная, дальше падает как 1/расстояние, после `range_max` — тишина.

`1/r` — не физика (в реальности энергия падает как 1/r², и для точечного
источника это было бы `1/r`... по амплитуде как раз `1/r`), а то, что
привычно звучит в играх. Настоящее физическое затухание кажется слишком
резким.

```c
	pan = v3_dot(v3_scale(delta, 1.0f / distance), ear_right);
	pan = m3_clampf(pan, -1.0f, 1.0f);

	*left = v->gain * attenuation * sqrtf((1.0f - pan) * 0.5f);
	*right = v->gain * attenuation * sqrtf((1.0f + pan) * 0.5f);
```

`pan` — скалярное произведение направления на источник и вектора «вправо» у
слушателя. Плюс единица — строго справа, минус единица — слева, ноль —
прямо перед или за.

Корень нужен для постоянной мощности. Если делить линейно (`0.5*(1-pan)` и
`0.5*(1+pan)`), сумма мощностей в середине панорамы окажется меньше, чем по
краям, и звук, проезжающий мимо, будет проваливаться посередине. С корнем
сумма квадратов всегда единица, и провала нет.

Направление «вправо» считается один раз при обновлении слушателя:

```c
void
snd_Listener(struct vec3 position, struct vec3 forward)
{
	ear_pos = position;
	ear_right = v3_norm(v3_cross(v3_norm(forward), v3(0.0f, 1.0f, 0.0f)));
}
```

Векторное произведение направления взгляда и вертикали. Ту же операцию
делает `m4_look_at` для камеры, потому что это одна и та же задача.

Различить «спереди» и «сзади» такая схема не может: у обоих `pan = 0`.
Именно эту задачу решает HRTF в OpenAL, и именно её ты решил не решать.

## Смешивание

```c
void
snd_Mix(short *out, int frames)
{
	for (f = 0; f < frames; f++) {
		out[f * 2 + 0] = 0;
		out[f * 2 + 1] = 0;
	}

	for (i = 0; i < SND_VOICES; i++) {
		v = &voices[i];
		if (!v->busy)
			continue;

		levels(v, &left, &right);

		for (f = 0; f < frames; f++) {
			index = v->position >> 16;
			if (index >= v->frames) {
				if (!v->loop) {
					v->busy = 0;
					break;
				}
				v->position = 0;
				index = 0;
			}
			...
			out[f * 2 + 0] = (short)clip(out[f * 2 + 0] + acc_l);
			out[f * 2 + 1] = (short)clip(out[f * 2 + 1] + acc_r);
			v->position += v->step;
		}
	}
}
```

Сначала выход обнуляется, потом каждый голос **прибавляется**. Порядок
циклов — голос снаружи, кадры внутри — выбран потому, что так громкости
считаются один раз на голос, а не на каждый кадр.

Побочный эффект того же выбора: громкость внутри одного блока постоянна.
При быстром движении источника на границе блоков может быть слышен щелчок.
Лечится линейным изменением громкости от начала блока к концу; в списке
дел.

```c
static int
clip(int sample)
{
	if (sample > 32767)
		return 32767;
	if (sample < -32768)
		return -32768;
	return sample;
}
```

Ограничение обязательно. Сумма нескольких громких звуков легко выходит за
диапазон `short`, и без ограничения произойдёт переполнение: громкий звук
превратится в противоположный по знаку, и вместо громкости получится
треск. Ограничение звучит как искажение, переполнение — как поломка.

## Как этим пользоваться

```c
	snd_Init(44100);                        /* один раз, зовёт app_Run */
	snd_SetRange(4.0f, 60.0f);              /* метры */

	snd_Listener(g->cam.pos, cam_Forward(&g->cam));   /* каждый кадр */
	snd_Play(&shot, gun_position, 1.0f, 0); /* пространственный, один раз */
	snd_Play2D(&music, 0.5f, 1);            /* без позиции, зациклен */
```

Слушатель ставится в камеру, а не в персонажа: игрок слышит оттуда, откуда
смотрит, и в третьем лице это заметно. Выбор спорный — часть игр ставит
слушателя в персонажа, чтобы звук соответствовал тому, кого касается урон.
Движку всё равно, `snd_Listener` берёт произвольную точку.

`snd_Play` возвращает номер голоса. Он нужен, только если звук надо
двигать (`snd_Move`) или прервать (`snd_Stop`). Для выстрела номер можно
выбросить.

Номер не проверяется на «тот же самый»: если голос закончился и его занял
другой звук, `snd_Stop` со старым номером остановит новый звук. Для игры
такого масштаба это допустимо; правильное решение — счётчик поколений в
старших битах дескриптора.

Микшер зовёт главный цикл, игре звать `snd_Mix` не нужно.

## Почему это не OpenAL

Всё, что выше, — двести пятьдесят строк без единой зависимости. OpenAL дал
бы то же самое плюс HRTF, эффект Доплера, реверберацию EFX и аппаратные
голоса. Это ровно тот список, который был не нужен.

Чего нельзя избежать никаким выбором библиотеки — способа отдать сэмплы
операционной системе. Это `plat_AudioWrite`, шестьдесят строк, глава 05.
