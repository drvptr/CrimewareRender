# 07. Рендер: как треугольник попадает на экран

Файлы `gfx/gfx.h`, `gfx/gfx_gl.c`, `gfx/gfx_null.c`. Самый плотный кусок
движка. Начнём с того, как вообще устроено рисование на видеокарте, потому
что без этого код читать бесполезно.

## Что делает видеокарта

Видеокарта умеет одно: взять список вершин и нарисовать из них
треугольники. Всё остальное — как именно раскрасить эти треугольники — она
спрашивает у двух маленьких программ, которые ты ей даёшь.

Конвейер:

```
массив вершин (в видеопамяти)
    |
    | для каждой вершины
    v
ВЕРШИННЫЙ ШЕЙДЕР   -> где эта вершина на экране + что передать дальше
    |
    | вершины собираются по три в треугольник,
    | треугольник разбивается на пиксели,
    | значения между вершинами интерполируются
    v
ФРАГМЕНТНЫЙ ШЕЙДЕР -> какого цвета этот пиксель
    |
    v
проверка глубины -> запись в буфер кадра
```

**Шейдер** — программа на языке GLSL, похожем на C, которая выполняется на
видеокарте. Вершинный запускается один раз на вершину, фрагментный — один
раз на пиксель. Их исходники лежат прямо в `gfx_gl.c` как строки и
компилируются драйвером при старте.

**VBO** (vertex buffer object) — массив вершин, лежащий в видеопамяти.
Отправить его туда надо один раз; потом рисование стоит одного вызова.

**IBO** (index buffer object) — массив номеров вершин. Треугольники
задаются не повтором вершин, а ссылками на них. У куба 8 углов и 12
треугольников: без индексов пришлось бы хранить 36 вершин, с индексами —
8 вершин и 36 маленьких чисел.

**Uniform** — переменная, одинаковая для всех вершин одного вызова
отрисовки. Матрица, цвет, направление света. Меняется между вызовами, не
внутри.

**Атрибут** — поле вершины: позиция, нормаль, координата текстуры. У каждой
вершины своё.

**Varying** — то, что вершинный шейдер передаёт фрагментному. Значения
интерполируются по треугольнику: если у трёх вершин цвет красный, зелёный
и синий, в середине получится смесь. Именно так работает затенение по Гуро.

## Договор `gfx.h`

```c
struct gfx_vertex {
	float x, y, z;      /* позиция */
	float nx, ny, nz;   /* нормаль */
	float u, v;         /* координата текстуры */
};
```

32 байта, восемь чисел, всё вперемешку (interleaved). Так, а не тремя
отдельными массивами, потому что видеокарта читает вершину целиком, и
данные, лежащие рядом, попадают в одну строку кэша.

**Нормаль** — единичный вектор, перпендикулярный поверхности в этой точке.
По нему считается освещение.

**Координата текстуры** (u, v) — точка на картинке, от 0 до 1 по обеим осям.
`(0,0)` — левый верхний угол, `(1,1)` — правый нижний. Значение 4 при
включённом повторе означает «уложить картинку четыре раза».

В интерфейсе нет ни одного типа OpenGL. Ни `GLuint`, ни `GLenum`.
Дескрипторы — `unsigned int`, матрицы — `float[16]`. Поэтому `gfx_null.c`
реализуется тридцатью пустыми функциями и игра этого не замечает.

## Загрузка точек входа

`gfx_gl.c` не включает ни одного заголовка OpenGL. Вместо этого — сорок
пять указателей на функции, объявленных руками:

```c
static void (*p_glDrawElements)(unsigned int, int, unsigned int,
    const void *);
static void (*p_glUniformMatrix4fv)(int, int, unsigned char, const float *);
```

Типы OpenGL расписаны тем, чем они на самом деле являются: `GLenum` — это
`unsigned int`, `GLint` — `int`, `GLsizei` — `int`. Никаких псевдонимов.

Константы тоже выписаны числами:

```c
#define GL_TRIANGLES		0x0004
#define GL_DEPTH_TEST		0x0B71
#define GL_ARRAY_BUFFER		0x8892
```

Это те же числа, что в `<GL/gl.h>`, они зафиксированы стандартом и не
меняются.

Загрузка — сорок пять строк подряд:

```c
	p_glClear = plat_GlProc("glClear");
	p_glClearColor = plat_GlProc("glClearColor");
	...
	if (p_glClear == 0 || p_glCreateProgram == 0 || ...) {
		fprintf(stderr, "gfx: this GL has no shaders (need 2.0)\n");
		return 0;
	}
```

Проверяются не все сорок пять, а четыре характерных. Если есть
`glCreateProgram`, значит это OpenGL 2.0 и всё остальное на месте.

## Шейдер, один на всё

Вершинный:

```glsl
attribute vec3 a_pos;
attribute vec3 a_nrm;
attribute vec2 a_uv;
uniform mat4 u_mvp;
uniform mat4 u_model;
uniform vec3 u_lightdir;
uniform float u_ambient;
uniform vec4 u_tint;
uniform float u_unlit;
varying vec2 v_uv;
varying vec4 v_col;
varying float v_dist;
void main(){
  vec4 clip = u_mvp * vec4(a_pos, 1.0);
  gl_Position = clip;
  vec3 n = normalize(vec3(u_model * vec4(a_nrm, 0.0)));
  float d = max(dot(n, -u_lightdir), 0.0);
  float l = min(u_ambient + d * (1.0 - u_ambient), 1.0);
  l = mix(l, 1.0, u_unlit);
  v_col = vec4(u_tint.rgb * l, u_tint.a);
  v_uv = a_uv;
  v_dist = clip.w;
}
```

Построчно:

1. Позиция вершины умножается на MVP и попадает в `gl_Position` — это
   обязанность вершинного шейдера, без этой строки ничего не нарисуется.
2. Нормаль поворачивается матрицей модели. Умножение с `w = 0` отбрасывает
   столбец переноса: нормаль — направление, её нельзя двигать вместе с
   объектом, иначе она перестанет быть перпендикуляром.
3. `dot(n, -u_lightdir)` — насколько поверхность повёрнута к свету. `max`
   с нулём отсекает отрицательное: поверхность, отвёрнутая от света, не
   светится «отрицательно», она просто в тени.
4. К результату добавляется фоновая подсветка, всё ограничивается
   единицей.
5. `u_unlit` выключает освещение целиком (для 2D и спрайтов). `mix(a,b,t)`
   — линейная смесь; при `t = 1` получается `b`, то есть яркость 1.
6. Яркость умножается на цвет и уходит во фрагментный шейдер.
7. `v_dist` = `clip.w` — расстояние до камеры, для тумана (глава 06).

Фрагментный:

```glsl
void main(){
  vec4 c = v_col;
  if (u_textured > 0.5)
    c = c * texture2D(u_tex, v_uv);
  if (c.a < 0.02)
    discard;
  float f = 0.0;
  if (u_fog.y > u_fog.x)
    f = clamp((v_dist - u_fog.x) / (u_fog.y - u_fog.x), 0.0, 1.0);
  gl_FragColor = vec4(mix(c.rgb, u_fogcol, f), c.a);
}
```

`texture2D` берёт цвет из текстуры. `discard` выбрасывает пиксель целиком —
так работает вырезание по альфе (листва, решётки, прицел). Дальше цвет
смешивается с цветом тумана по расстоянию.

Обе ветки — `if` по uniform-переменной. Все вершины одного вызова идут по
одной ветке, предсказание идеальное, стоимость нулевая. Зато вместо
четырёх шейдеров (текстурированный, нетекстурированный, освещённый,
неосвещённый) один.

### Почему нет `#version`

Шейдер без директивы `#version` компилируется как GLSL 1.10 — так написано
в спецификации, и так делает любой драйвер, хоть свежий, хоть
двадцатилетний. Поэтому шейдер написан строго в рамках 1.10, и это
единственный диалект, который заодно совпадает с GLES2. Один исходник
работает и на десктопе, и на телефоне.

Практический след этого решения в коде: `mat3(u_model)` писать нельзя, это
1.20. Отсюда форма с `vec4(a_nrm, 0.0)`.

## Компиляция и линковка шейдера

```c
	id = p_glCreateShader(kind);
	p_glShaderSource(id, 1, &src, 0);
	p_glCompileShader(id);
	p_glGetShaderiv(id, GL_COMPILE_STATUS, &ok);
	if (!ok) {
		p_glGetShaderInfoLog(id, sizeof log, 0, log);
		fprintf(stderr, "gfx: %s shader will not compile:\n%s\n",
		    what, log);
		return 0;
	}
```

Шейдер компилируется драйвером при каждом запуске программы. Ошибку надо
печатать обязательно: без лога ты видишь чёрный экран и не знаешь, что
случилось.

```c
	p_glBindAttribLocation(prog, 0, "a_pos");
	p_glBindAttribLocation(prog, 1, "a_nrm");
	p_glBindAttribLocation(prog, 2, "a_uv");
	p_glLinkProgram(prog);
```

Номера атрибутов назначаются **до** линковки. Иначе драйвер раздаст их сам,
и придётся спрашивать, какой достался кому. Фиксируя номера, мы получаем
право писать `p_glVertexAttribPointer(0, ...)` без запроса.

После линковки берутся адреса uniform-переменных:

```c
	u_mvp = p_glGetUniformLocation(prog, "u_mvp");
```

Если переменная не используется в шейдере, компилятор её выбросит и вернёт
`-1`. Поэтому каждое присваивание защищено проверкой `if (u_xxx >= 0)`.

## Дескрипторы мешей

```c
struct gl_mesh {
	unsigned int vbo;
	unsigned int ibo;
	int nindex;
	int nverts;
	int used;
};

static struct gl_mesh meshes[GFX_MAX_MESHES];
```

Массив на тысячу штук, дескриптор — индекс плюс единица (чтобы ноль
означал «ничего»). Ни `malloc`, ни списка.

```c
static struct gl_mesh *
mesh_at(unsigned int handle)
{
	if (handle == 0 || handle > GFX_MAX_MESHES)
		return 0;
	if (!meshes[handle - 1].used)
		return 0;
	return &meshes[handle - 1];
}
```

Каждый вызов проверяет дескриптор. Испорченный или устаревший номер даёт
тихий возврат, а не падение.

Текстуры устроены иначе: там дескриптором служит сам номер объекта OpenGL,
потому что ничего кроме него хранить не надо.

## Создание меша

```c
	p_glGenBuffers(1, &m->vbo);
	p_glBindBuffer(GL_ARRAY_BUFFER, m->vbo);
	p_glBufferData(GL_ARRAY_BUFFER, nverts * sizeof(struct gfx_vertex),
	    verts, usage);
```

OpenGL устроен как машина состояний: сначала «сделать текущим» (`Bind`),
потом операция над текущим. Это выглядит громоздко, но так работает вся
библиотека.

`usage` — подсказка драйверу: `GL_STATIC_DRAW` («записал и больше не трогаю»)
или `GL_DYNAMIC_DRAW` («буду переписывать каждый кадр»). От неё зависит,
куда именно драйвер положит данные. Для анимированной модели нужен второй.

## Отрисовка

```c
static void
draw_indexed(struct gl_mesh *m, const float model[16], unsigned int tex,
    const float rgba[4], int first, int count, float unlit)
{
	m4_mul(mvp, cur_viewproj, model);
	p_glUniformMatrix4fv(u_mvp, 1, 0, mvp);
	p_glUniformMatrix4fv(u_model, 1, 0, model);
	p_glUniform4fv(u_tint, 1, rgba != 0 ? rgba : white);
	p_glUniform1f(u_unlit, unlit);
	p_glUniform1f(u_textured, tex != 0 ? 1.0f : 0.0f);

	if (tex != 0) {
		p_glActiveTexture(GL_TEXTURE0);
		p_glBindTexture(GL_TEXTURE_2D, tex);
	}

	bind_attributes(m);
	p_glDrawElements(GL_TRIANGLES, count, GL_UNSIGNED_SHORT,
	    (const void *)((long)first * sizeof(unsigned short)));
	draw_calls++;
}
```

`bind_attributes` объясняет видеокарте, как разложена вершина:

```c
	p_glVertexAttribPointer(0, 3, GL_FLOAT, 0, stride, (const void *)0);
	p_glVertexAttribPointer(1, 3, GL_FLOAT, 0, stride,
	    (const void *)(3 * sizeof(float)));
	p_glVertexAttribPointer(2, 2, GL_FLOAT, 0, stride,
	    (const void *)(6 * sizeof(float)));
```

Читается как «атрибут 0 — три float, шаг 32 байта, начиная со смещения 0;
атрибут 1 — три float с того же шага, смещение 12; атрибут 2 — два float,
смещение 24». Указатель здесь не указатель, а смещение внутри буфера —
наследие старого API, где массивы лежали в обычной памяти.

`first` и `count` — диапазон индексов. Это то, чем рисуются материальные
группы `.obj`: одна модель, три текстуры, три вызова с разными диапазонами.

## Спрайты

Спрайт — плоская картинка, всегда повёрнутая к камере. Взрывы, искры,
трава, полоска здоровья над врагом.

```c
	right = v3(cur_view[0], cur_view[4], cur_view[8]);
	up = v3(cur_view[1], cur_view[5], cur_view[9]);
```

Оси камеры лежат прямо в матрице вида: строки её верхнего левого блока 3×3.
Взяв их, мы строим квадрат в плоскости экрана — он гарантированно смотрит
на камеру при любом её повороте.

```c
	p_glDisable(GL_CULL_FACE);
	draw_indexed(m, model, tex, rgba, 0, 6, 1.0f);
	p_glEnable(GL_CULL_FACE);
```

Отсечение выключается: если камера обойдёт спрайт сзади, обход вершин
окажется обратным и квадрат исчезнет.

## 2D

```c
void
gfx_Begin2D(void)
{
	m4_copy(saved_view, cur_view);
	m4_copy(saved_proj, cur_proj);
	m4_ortho(ortho, 0.0f, (float)screen_w, (float)screen_h, 0.0f,
	    -1.0f, 1.0f);
	m4_identity(ident);
	gfx_SetCamera(ident, ortho);
	p_glDisable(GL_DEPTH_TEST);
	p_glDisable(GL_CULL_FACE);
}
```

Ортографическая проекция вместо перспективной: дальнее не уменьшается,
координаты равны пикселям. Обрати внимание на порядок аргументов:
`bottom = screen_h`, `top = 0`, то есть ось Y перевёрнута, и начало
координат в левом верхнем углу, как принято в интерфейсах.

Глубина выключается: интерфейс рисуется поверх всего в порядке вызовов.
Отсечение выключается, чтобы не думать об обходе вершин у прямоугольников.

`gfx_End2D` возвращает сохранённые матрицы обратно.

## Отсечение задних граней

Включено по умолчанию:

```c
	p_glEnable(GL_CULL_FACE);
```

Треугольник считается лицевым, если его вершины обходятся против часовой
стрелки с точки зрения камеры. Задние отбрасываются до растеризации, и
половина треугольников замкнутой модели не стоит ничего.

Отсюда самая частая непонятная ошибка новичка: **модель есть, а на экране
пусто**, или комната видна снаружи и прозрачна изнутри. Причина — обратный
порядок вершин. Проверяется мгновенно: временно поставить
`p_glDisable(GL_CULL_FACE)` в `gfx_BeginFrame`; если картинка появилась,
дело в обходе.

## Буфер глубины

```c
	p_glEnable(GL_DEPTH_TEST);
	p_glDepthFunc(GL_LEQUAL);
```

Для каждого пикселя экрана хранится расстояние до ближайшей уже
нарисованной поверхности. Новый пиксель пишется, только если он ближе.
Поэтому объекты можно рисовать в любом порядке, и они правильно перекроют
друг друга.

Это то, ради чего в 1996 году строили BSP-деревья, а сегодня оно есть в
любой видеокарте бесплатно. Отсюда решение не делать BSP (`docs/04-decisions.md`).

Ограничение: прозрачность буфер глубины не решает. Прозрачные поверхности
надо рисовать после всех непрозрачных и в порядке от дальних к ближним.
Сейчас движок этого не делает; в списке дел.

## Пустой бэкенд

```c
void
gfx_DrawMesh(unsigned int mesh, const float model[16], unsigned int tex,
    const float rgba[4], int first, int count)
{
	(void)mesh;
	...
	draw_calls++;
}
```

`(void)x;` — способ сказать компилятору «параметр не используется
намеренно», чтобы `-Wunused-parameter` молчал.

Смысл файла в том, что игра, собранная с ним, выполняет ровно тот же код,
что и настоящая: та же загрузка, те же коллизии, тот же портальный обход.
Не выполняется только рисование. Отсюда возможность гонять тесты и
логику там, где нет ни экрана, ни видеокарты.
