# 12. Своя игра с нуля

Практическая глава. Пустой каталог превращается в играбельное нечто, потом
разбираются типичные ошибки.

## Шаг 1: пустое окно

Создай `game/main.c`:

```c
#include <stdio.h>
#include "../core/app.h"
#include "../core/arena.h"
#include "../gfx/gfx.h"

static char pool[32 * 1024 * 1024];

struct game {
	struct arena mem;
	float t;
};

static int
game_init(void *user)
{
	struct game *g = (struct game *)user;

	arena_Init(&g->mem, pool, (long)sizeof pool);
	return 0;
}

static void
game_step(void *user, float dt)
{
	struct game *g = (struct game *)user;

	g->t += dt;
	if (app_Input()->hit[PLAT_KEY_ESC])
		app_Quit();
}

static void
game_draw(void *user, float alpha)
{
	(void)user;
	(void)alpha;
	gfx_BeginFrame(0.1f, 0.1f, 0.15f);
}

int
main(void)
{
	static struct game g;
	struct app_hooks hooks;

	hooks.title = "my game";
	hooks.width = 1024;
	hooks.height = 640;
	hooks.step_hz = 60.0f;
	hooks.max_fps = 250;
	hooks.audio_rate = 44100;
	hooks.init = game_init;
	hooks.step = game_step;
	hooks.draw = game_draw;
	hooks.quit = 0;
	hooks.user = &g;

	return app_Run(&hooks);
}
```

В `Makefile` замени `DEMO = demo/main.c` на `DEMO = game/main.c`. Собери,
запусти: синее окно, закрывается по Escape и по крестику. Это уже готовый
каркас, дальше только добавление.

## Шаг 2: что-то на экране

Куб проще всего построить в коде. Понадобится вспомогательная функция для
четырёхугольника — возьми `quad()` и `room()` из `demo/main.c`, они
написаны ровно для этого.

```c
	g->room_mesh = gfx_MakeMesh(b.v, b.nv, b.i, b.ni, 0);
```

и в `draw`:

```c
	float view[16], proj[16];
	float white[4] = { 1.0f, 1.0f, 1.0f, 1.0f };
	float model[16];

	m4_fps_view(view, g->eye, g->yaw, g->pitch);   /* пока так, см. шаг 3.5 */
	m4_perspective(proj, 1.2f, (float)app_Width() / app_Height(),
	    0.1f, 200.0f);

	gfx_BeginFrame(0.1f, 0.1f, 0.15f);
	gfx_SetCamera(view, proj);
	m4_identity(model);
	gfx_DrawMesh(g->room_mesh, model, 0, white, 0, -1);
```

Текстуры нет — передан ноль, и меш нарисуется однотонным. Так и надо
начинать: сначала убедиться, что геометрия на месте.

**Ничего не видно?** По порядку:

1. Камера внутри объекта или смотрит в другую сторону. Отойди назад
   (`g->eye.z = 10`).
2. Обход вершин обратный. Временно поставь `p_glDisable(GL_CULL_FACE)` в
   `gfx_BeginFrame` — если появилось, дело в этом.
3. Объект за дальней плоскостью или ближе ближней.
4. `gfx_DrawCalls()` вернул ноль — значит, вызов отрисовки не дошёл, и
   проблема не в графике, а в дескрипторе меша.

## Шаг 3: ходить

```c
	forward = v3(sinf(g->yaw), 0.0f, -cosf(g->yaw));
	right = v3(cosf(g->yaw), 0.0f, sinf(g->yaw));

	wish = v3(0.0f, 0.0f, 0.0f);
	if (in->hold['W'])
		wish = v3_add(wish, forward);
	if (in->hold['S'])
		wish = v3_sub(wish, forward);
	if (in->hold['D'])
		wish = v3_add(wish, right);
	if (in->hold['A'])
		wish = v3_sub(wish, right);

	wish = v3_scale(v3_norm(wish), 4.0f);
```

`v3_norm` обязателен. Без него движение по диагонали (W и D вместе) окажется
в 1.41 раза быстрее, чем прямо, — классическая ошибка, известная как
strafe-jumping, и в Quake она была не задумана, а именно такой.

Обзор:

```c
	g->yaw += (float)in->mouse_dx * 0.0025f;
	g->pitch -= (float)in->mouse_dy * 0.0025f;
	g->pitch = m3_clampf(g->pitch, -1.5f, 1.5f);
```

Знак `pitch` минусовый, потому что экранная ось Y растёт вниз, а взгляд
вверх — это плюс. Ограничение обязательно, иначе на 90 градусах камера
перевернётся (глава 06).

Не забудь `plat_GrabMouse(1)` в `init`, иначе курсор уйдёт за край окна.

Пока камера и персонаж — одна переменная `g->eye`, и на этом шаге это
нормально: игра от первого лица, и разделять нечего. Следующий шаг
объясняет, почему разделить всё равно надо, и делает это до того, как на
`g->eye` завяжется остальной код.

## Шаг 3.5: камера отдельно от персонажа

Соблазн держать одну переменную на позицию камеры и позицию игрока велик, и
пока игра от первого лица, он ничего не стоит. Стоить он начнёт в тот день,
когда захочется вид сзади, вид сверху, повтор матча, камера наблюдения или
второй управляемый персонаж, — то есть примерно на второй неделе.

Разделять дёшево. Персонаж:

```c
struct unit {
	struct vec3 pos;
	struct vec3 velocity;
	float yaw;
	int on_floor;
};
```

Камера — в `demo/camera.h`, копируй к себе. Вся её суть в одной функции:

```c
	anchor = v3_add(target, v3(0.0f, c->eye_height, 0.0f));
	back = v3_scale(cam_Forward(c), -c->distance);
	/* луч от anchor вдоль back: если стена ближе, поводок короче */
	c->pos = v3_add(anchor, v3_scale(back, best));
```

`distance = 0` даёт первое лицо, `4` — вид сзади, `18` со steep-наклоном —
вид сверху. Луч против солидов обязателен для третьего лица: без него
камера уезжает в соседнюю комнату и показывает изнанку стен.

Дальше в `step` порядок такой:

```c
	for (i = 0; i < UNITS; i++)
		unit_step(g, &g->unit[i], i == g->controlled ? wish : zero, dt);

	cam_Update(&g->cam, g->unit[g->controlled].pos, near_solids, n);
	snd_Listener(g->cam.pos, cam_Forward(&g->cam));
```

Сначала все, кто ходит, потом камера. Наоборот — картинка отстаёт на кадр.

Движение считается от осей КАМЕРЫ, а не персонажа:

```c
	right = cam_Right(&g->cam);
	forward = v3(right.z, 0.0f, -right.x);
```

Игрок жмёт W и ожидает, что пойдёт туда, куда смотрит экран. Если считать
от разворота модели, в третьем лице управление станет непредсказуемым.

Для стратегии меняется ровно одно: точкой интереса становится свободная
точка карты, а не персонаж, и клавиши двигают её. Приказ — это поле в
юните:

```c
	if (in->hit[' ']) {
		g->unit[g->controlled].has_order = 1;
		g->unit[g->controlled].order = g->map_focus;
	}
```

и в `unit_step`:

```c
	if (u->has_order) {
		to = v3_sub(u->order, u->pos);
		to.y = 0.0f;
		if (v3_len(to) < 0.4f)
			u->has_order = 0;
		else
			wish = v3_scale(v3_norm(to), 3.0f);
	}
```

Юниту всё равно, откуда взялось `wish` — с клавиатуры, из приказа или от
ИИ. Это и есть та граница, ради которой всё разделялось.

## Шаг 4: стены

```c
	int hall = wld_AddSector(&g->world, box(-8, 0, -8, 8, 4, 8),
	    g->room_mesh, g->wall_tex);
	wld_AddSolid(&g->world, hall, box(-1.5f, 0, -1.5f, 1.5f, 1, 1.5f));
```

и в `step`:

```c
	struct unit *u = &g->unit[g->controlled];
	struct aabb body = coll_MakeAabb(u->pos, v3(0.35f, 0.9f, 0.35f));
	struct aabb near[64];
	int here = wld_SectorAt(&g->world, u->pos);
	int n = wld_SolidsNear(&g->world, &here, 1, near, 64);

	u->velocity.x = wish.x;
	u->velocity.z = wish.z;
	u->velocity.y -= 18.0f * dt;

	u->pos = v3_add(u->pos, coll_MoveAabb(body,
	    v3_scale(u->velocity, dt), near, n, &u->on_floor));
```

Сектор берётся вокруг **тела**. Для видимости в `draw` надо будет взять
сектор вокруг камеры — это разные вызовы, и в третьем лице они дают разные
секторы чаще, чем одинаковые.

Обрати внимание: горизонтальная скорость **присваивается**, вертикальная
**накапливается**. Персонаж в играх не имеет инерции по горизонтали (иначе
управление кажется скользким), но подчиняется гравитации по вертикали.

Прыжок:

```c
	if (u->on_floor && in->hold[' '])
		u->velocity.y = 6.0f;
```

`on_floor` заполняет `coll_MoveAabb`, отдельная проверка не нужна.

## Шаг 5: текстура

```c
	long mark = arena_Mark(&g->mem);
	long len;
	void *file = slurp(&g->mem, "data/wall.tga", &len);

	if (file != 0 && tga_Probe(file, len)) {
		unsigned long long geo = tga_Geo(file);
		void *px = arena_Alloc(&g->mem, tga_CanvasBytes(file), 4);
		if (tga_Decode(px, tga_CanvasBytes(file), file, len) == 0)
			g->wall_tex = gfx_MakeTexture(px, geo, 1, 1);
	}
	arena_Reset(&g->mem, mark);
```

`slurp` возьми из `demo/main.c` — это функция игры, не движка.

**Текстура чёрная или белая?** Три причины по убыванию частоты:

1. Файл не нашёлся. `slurp` печатает об этом; проверь текущий каталог, из
   которого запускаешь.
2. Формат не поддержан: палитра или 16 бит. `tga_Probe` вернёт 0. Пересохрани
   как 24 или 32 бита без сжатия.
3. Размер не степень двойки вместе с `GL_REPEAT` на старом драйвере.
   Поставь последний аргумент `gfx_MakeTexture` в 0 и проверь.

## Шаг 6: модель

```c
	void *file = slurp(&g->mem, "data/guard.obj", &len);
	if (file != 0 && obj_Parse(&g->model, file, len, &g->mem) == 0)
		g->model_mesh = gfx_MakeMesh(g->model.verts, g->model.nverts,
		    g->model.index, g->model.nindex, 0);
```

Здесь `arena_Reset` не зовём: вершины нужны и дальше.

Модель с несколькими материалами рисуется по группам:

```c
	for (i = 0; i < g->model.ngroups; i++) {
		unsigned int tex = texture_by_name(g, g->model.groups[i].name);
		gfx_DrawMesh(g->model_mesh, model, tex, white,
		    g->model.groups[i].first, g->model.groups[i].count);
	}
```

`texture_by_name` пишешь ты: движок не знает, где лежат твои текстуры.
Простейший вариант — массив пар «имя, дескриптор» и линейный поиск.

## Шаг 7: звук и интерфейс

```c
	snd_Listener(g->cam.pos, cam_Forward(&g->cam));
	if (in->hit[PLAT_MOUSE_L])
		snd_Play(&g->shot, g->unit[g->controlled].pos, 1.0f, 0);
```

`hit`, а не `hold`: иначе за одно нажатие выстрелов будет шестьдесят.

```c
	gui_Begin(app_Input());
	gui_SetColor(1.0f, 1.0f, 1.0f, 0.75f);
	gui_Rect(app_Width() * 0.5f - 6, app_Height() * 0.5f - 1, 12, 2);
	gui_Rect(app_Width() * 0.5f - 1, app_Height() * 0.5f - 6, 2, 12);
	gui_End();
```

Прицел из двух прямоугольников. Меню — там же, по состоянию:

```c
	if (g->paused) {
		gui_SetColor(0, 0, 0, 0.7f);
		gui_Rect(0, 0, app_Width(), app_Height());
		gui_SetColor(1, 1, 1, 1);
		if (gui_Button(40, 40, 200, 36, "CONTINUE"))
			g->paused = 0;
		if (gui_Button(40, 86, 200, 36, "QUIT"))
			app_Quit();
	}
```

Не забудь отпустить мышь на паузе (`plat_GrabMouse(0)`), иначе курсором не
попасть по кнопке.

## Ошибки, которые сделает каждый

**Логика в `draw`.** Работает, пока не запустишь на другой машине. Правило
без исключений: `draw` не меняет ничего, `step` не рисует ничего.

**Умножение на `dt` в `step`.** Здесь это как раз правильно, но `dt` — всегда
одна и та же константа. Если начнёшь считать `dt` сам от времени кадра,
вернёшься к проблемам из главы 03.

**Забытый `v3_norm`.** Диагональ быстрее прямой; нормаль ненулевой длины
ломает освещение; направление взгляда без нормализации портит панораму
звука.

**Арена откачена слишком рано.** `wav_Parse` не копирует сэмплы. Откатишь
арену — микшер читает мусор и играет шум. То же с `anim_Parse`: кадры
лежат в твоём буфере.

**Порядок умножения матриц.** `m4_mul(out, a, b)` значит «сначала b, потом
a». Читать справа налево. Перепутанный порядок масштаба и переноса —
самая частая причина «модель уехала куда-то».

**Солиды не в том порядке.** `wld_AddSolid` работает только с последним
созданным сектором и возвращает -1 иначе. Возврат обычно никто не
проверяет, и препятствия молча не добавляются.

**Прозрачность поверх прозрачности.** Движок не сортирует прозрачные
поверхности. Два стекла друг за другом покажут артефакты. Пока лечится
порядком вызовов вручную.

**`hold` вместо `hit`.** Очередь из шестидесяти выстрелов, дверь, которая
открывается и закрывается шестьдесят раз в секунду.

**Одна переменная на камеру и на персонажа.** Работает ровно до первого
вида сзади. Разделять надо сразу, это две структуры и тридцать строк.

**Видимость от сектора персонажа, а не камеры.** В третьем лице они разные
чаще, чем одинаковые, и симптом будет странный: комната пропадает, когда
персонаж проходит в дверь.

## Что делать дальше

Когда каркас работает, вопросы обычно такие.

**Врагов много, ИИ где?** Нигде, и это намеренно. ИИ — часть игры. Начни с
массива структур и `switch` по состоянию: патрулирует, увидел, стреляет,
убегает. Конечный автомат на сотню строк закрывает потребности игры уровня
PS2 целиком.

**Как сохраняться?** Пока `struct game` не содержит указателей, сохранение —
это `fwrite(&g, sizeof g, 1, f)`. Как только появятся указатели друг на
друга, придётся заменять их индексами. Лучше не заводить их вовсе.

**Уровень строится кодом, это неудобно.** Напиши свой текстовый формат и
загрузчик к нему: имена `.obj` по секторам, порталы, солиды, точки старта.
Двести строк на разбор, и уровни станут правиться без пересборки. Движок
для этого менять не придётся — он и так принимает готовые меши.

**Нужны тени.** Начни с blob-тени: луч вниз через `coll_RayAabb`, круглая
текстура с альфой, прямоугольник на найденной высоте, чуть выше пола.
Выглядит как PS2, потому что там это так и делалось.
