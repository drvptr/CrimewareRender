# 09. Мир: секторы, порталы, коллизии

Каталог `world/`. Два файла: `world.c` отвечает на вопрос «что видно»,
`coll.c` — на вопрос «куда можно идти».

## Зачем вообще решать, что видно

Видеокарта отбросит невидимое сама: то, что за краем экрана, отсечётся, то,
что за стеной, не пройдёт проверку глубины. Но заплатить за это придётся
всё равно — каждая вершина пройдёт через шейдер, каждый треугольник будет
растеризован.

Поэтому задача ставится раньше: не отправлять на видеокарту то, чего точно
не видно. Способов два.

**Отбраковка по фрустуму** — проверить, попадает ли объект в поле зрения
(глава 06). Дёшево, но не помогает против стены: комната за стеной вполне в
поле зрения.

**Определение видимости** — понять, что комната за стеной не видна, потому
что между нами глухая стена. Вот это и делают порталы.

## Секторы и порталы

```c
struct wld_sector {
	struct aabb bounds;    /* границы */
	unsigned int mesh;     /* что рисовать */
	unsigned int tex;
	int first_solid;       /* чем занята */
	int nsolids;
};

struct wld_portal {
	struct vec3 corner[4];
	int from;
	int to;
};
```

Сектор — комната. Портал — дверной проём: четырёхугольник и номер сектора,
который за ним.

Порталы односторонние. Из холла в комнату — один портал, из комнаты в холл
— второй, с обратным порядком углов. Так сделано потому, что порталы бывают
и односторонними по смыслу (окно, через которое видно улицу, но с улицы
внутрь не видно из-за отражений), а главное — двусторонний портал в
обходе всё равно пришлось бы рассматривать дважды.

## Обход

```c
	head = 0;
	tail = 0;
	queue[tail++] = from;
	seen[from] = 1;

	while (head < tail && n < max) {
		here = queue[head++];
		out[n++] = here;

		for (i = 0; i < w->nportals; i++) {
			p = &w->portal[i];
			if (p->from != here)
				continue;
			if (seen[p->to])
				continue;
			if (!portal_in_frustum(&f, p))
				continue;
			if (!fr_test_aabb(&f, w->sector[p->to].bounds.min,
			    w->sector[p->to].bounds.max))
				continue;
			seen[p->to] = 1;
			queue[tail++] = p->to;
		}
	}
```

Это обход в ширину. Начинаем с сектора, где стоит камера. Смотрим его
порталы. Тот, что попал в поле зрения, добавляет свой сектор в очередь. И
так далее, пока очередь не кончится.

`seen` не даёт зайти в сектор дважды и заодно исключает бесконечный цикл в
кольцевой планировке.

Массив `queue` и массив `seen` — локальные, на стеке, фиксированного
размера. Никаких выделений: обход происходит каждый кадр, и аллокация в нём
была бы обидной.

Порядок результата — от ближнего к дальнему (обход в ширину даёт слои по
числу порталов). Это удобно: рисуя ближнее первым, чаще выигрываешь на
проверке глубины.

### Проверка портала

```c
static int
portal_in_frustum(const struct frustum *f, const struct wld_portal *p)
{
	box.min[0] = p->corner[0].x;
	...
	for (i = 1; i < 4; i++)
		coll_AabbGrow(&box, p->corner[i]);

	for (i = 0; i < 3; i++) {
		box.min[i] -= 0.01f;
		box.max[i] += 0.01f;
	}
	return fr_test_aabb(f, box.min, box.max);
}
```

Вокруг четырёх углов строится коробка, и она проверяется фрустумом.
Сантиметр толщины добавлен потому, что портал плоский: коробка нулевой
толщины по одной из осей проваливает проверки из-за ошибок округления.

Это упрощённая версия. Классический алгоритм сужает фрустум по мере
прохода: за второй дверью видно только то, что попадает и в первый проём, и
во второй. Здесь фрустум не сужается, поэтому изредка рисуется сектор,
которого на самом деле не видно. Лишний вызов отрисовки против сотни строк
кода — размен сознательный, и в комментарии к файлу он записан.

### От чьего лица считать

`wld_Visible` принимает номер сектора, а не «игрока» и не «камеру».
Передавать туда надо сектор **камеры**: рисуется то, что видно ей. В игре
от третьего лица это часто не тот сектор, где стоит персонаж, — он уже
прошёл в дверь, а камера ещё позади.

Столкновения при этом считаются наоборот, вокруг тела, и для каждого тела
своего. Две задачи, две точки, и путать их нельзя:

```c
	nsolids = wld_SolidsNear(&world, &unit_sector, 1, near, 64);
	nsectors = wld_Visible(&world, camera_sector, viewproj, list, 16);
```

### Запасной вариант

```c
	if (from < 0 || from >= w->nsectors) {
		for (i = 0; i < w->nsectors && n < max; i++) {
			if (fr_test_aabb(&f, ...))
				out[n++] = i;
		}
		return n;
	}
```

Если камера не в секторе (вышли на улицу, где секторов нет), обход
невозможен, и работает обычная отбраковка по фрустуму. Так открытые
пространства не требуют отдельной подсистемы.

## Солиды

```c
int
wld_AddSolid(struct world *w, int sector, struct aabb box)
{
	if (sector != w->nsectors - 1)
		return -1;
	...
}
```

Странное на вид условие: добавлять солиды можно только к последнему
созданному сектору. Причина в раскладке: сектор владеет непрерывным куском
общего массива, у него хранится начало и количество.

```c
int
wld_SolidsNear(const struct world *w, const int *sectors, int nsectors,
    struct aabb *out, int max)
{
	for (j = 0; j < s->nsolids && n < max; j++)
		out[n++] = w->solid[s->first_solid + j];
}
```

Благодаря этому «дай мне препятствия рядом» — копирование подряд лежащих
элементов, а не обход списка. Взамен приходится строить уровень по порядку:
сектор, его солиды, следующий сектор. Функция за этим следит и возвращает
ошибку, а не портит данные молча.

Из этого следует приятное свойство: коллизии наследуют видимость. Проверять
столкновения нужно только с тем, что в текущем секторе, а не со всем
уровнем.

## AABB

```c
struct aabb {
	float min[3];
	float max[3];
};
```

Axis-aligned bounding box: коробка, грани которой параллельны осям
координат. Она не поворачивается. Именно поэтому все проверки с ней
сводятся к сравнениям чисел:

```c
int
coll_AabbAabb(const struct aabb *a, const struct aabb *b)
{
	for (i = 0; i < 3; i++) {
		if (a->max[i] < b->min[i])
			return 0;
		if (a->min[i] > b->max[i])
			return 0;
	}
	return 1;
}
```

Две коробки пересекаются, если они пересекаются по всем трём осям. Шесть
сравнений.

Цена — коробка вокруг наклонного объекта заметно больше самого объекта. Для
игры это почти всегда неважно: игрок и так воспринимает столкновения грубо.

## Сфера против коробки

```c
	for (i = 0; i < 3; i++)
		nearest[i] = m3_clampf(c[i], b->min[i], b->max[i]);

	for (i = 0; i < 3; i++)
		d[i] = c[i] - nearest[i];
	dist = sqrtf(d[0] * d[0] + d[1] * d[1] + d[2] * d[2]);

	if (dist > radius)
		return 0;
```

Приём, который стоит запомнить: ближайшая к точке точка коробки получается
простым ограничением координат её границами. Дальше остаётся сравнить
расстояние с радиусом.

Если центр сферы **внутри** коробки, расстояние равно нулю, направление
выталкивания неизвестно, и работает отдельная ветка: искать грань, до
которой ближе всего, и выталкивать через неё. Без этого объект, оказавшийся
внутри стены, вылетал бы в случайную сторону.

## Луч против треугольника

`coll_RayTri` — алгоритм Мёллера и Трумбора. Стандартный, его стоит просто
принять как данность; важно, что он не требует заранее посчитанной
плоскости и сразу даёт барицентрические координаты попадания.

```c
	det = v3_dot(e1, pv);
	if (det > -0.000001f && det < 0.000001f)
		return 0;
```

Определитель около нуля значит, что луч параллелен плоскости треугольника.
Проверка на близость к нулю, а не на равенство: точное сравнение с нулём в
арифметике с плавающей точкой почти всегда ошибка.

`coll_RayMesh` — перебор всех треугольников модели. Для выстрела по одному
врагу это бесплатно. Вызывать его по всему уровню для каждой пули без
предварительного сужения через сектор нельзя, и в заголовке об этом
написано.

## Движение с коллизиями

Самая полезная функция файла:

```c
struct vec3 coll_MoveAabb(struct aabb body, struct vec3 move,
    const struct aabb *solids, int nsolids, int *hit_ground);
```

«Подвинуть коробку на `move`, остановившись у препятствий». Возвращает,
насколько удалось продвинуться.

### Свип через Минковского

```c
static int
sweep_one(struct vec3 centre, struct vec3 half, struct vec3 move,
    const struct aabb *solid, float *t_out, int *axis_out)
{
	grown.min[0] = solid->min[0] - half.x;
	grown.max[0] = solid->max[0] + half.x;
	...
```

Приём: вместо того чтобы двигать коробку и проверять пересечение на каждом
шаге, препятствие раздувается на половину размера движущейся коробки, а
сама коробка превращается в точку. Задача «коробка против коробки в
движении» становится задачей «луч против коробки», а её мы уже умеем.

Это разность Минковского. Пугающее название у совершенно простого приёма.

Дальше — обычный проход по трём осям с сужением интервала:

```c
		t1 = (grown.min[i] - o[i]) / d[i];
		t2 = (grown.max[i] - o[i]) / d[i];
		if (t1 > t2) { поменять местами }
		if (t1 > tmin) { tmin = t1; axis = i; }
		if (t2 < tmax) tmax = t2;
		if (tmin > tmax)
			return 0;
```

`tmin` — момент входа, `tmax` — момент выхода. Если вход позже выхода,
пересечения нет. Ось, давшая последний `tmin`, — та, по которой произошло
касание, и по ней потом гасится скорость.

### Скольжение

```c
	for (pass = 0; pass < 3; pass++) {
		/* найти ближайшее препятствие */
		...
		step = v3_scale(move, best_t);
		centre = v3_add(centre, step);
		total = v3_add(total, step);

		if (best_axis < 0)
			break;

		if (best_axis == 0)
			move.x = 0.0f;
		else if (best_axis == 1) {
			if (move.y < 0.0f && hit_ground != 0)
				*hit_ground = 1;
			move.y = 0.0f;
		} else
			move.z = 0.0f;

		move = v3_scale(move, 1.0f - best_t);
	}
```

Три прохода. Первый упирается в стену и обнуляет составляющую скорости,
направленную в неё. Остаток движения — вдоль стены, и второй проход
пробует пройти его. Третий нужен для угла, где стены две.

Без скольжения игрок, идущий в стену под углом, вставал бы намертво. С ним
он скользит вдоль неё, как во всех играх от первого лица.

Побочная польза: касание с осью Y вниз — это и есть «стоит на земле», и
отдельного луча вниз для проверки прыжка не нужно.

```c
		if (best_axis >= 0) {
			best_t -= 0.0005f;
			if (best_t < 0.0f)
				best_t = 0.0f;
		}
```

Полмиллиметра недохода до поверхности. Без этого объект останавливается
ровно на грани, и в следующем кадре арифметика с плавающей точкой решает,
внутри он или снаружи. Решает не всегда одинаково, и получается дрожание
или проваливание. Такой отступ есть в любом движке, и величина подбирается
опытом.

## Что здесь сознательно не сделано

Нет массы, нет импульса, нет трения, нет вращения, нет решателя
ограничений. Это не «упрощённая физика», это отсутствие физики: набор
геометрических вопросов с точными ответами.

Для игры уровня PS2 этого достаточно, и это делает поведение
предсказуемым. Настоящая физика тел — отдельный большой проект, который
вдобавок усложняет дизайн уровней: ящик, который можно толкать, обязательно
застрянет в двери.
