# 08. Загрузчики: TGA, OBJ, WAV, VAN

Каталог `asset/`. Четыре загрузчика, устроенные по одному образцу: на вход
указатель и длина, на выход буфер в арене. Ни один не открывает файл.

Сначала — про геометрию буфера, потому что на ней держится TGA.

## Геометрия буфера

Файл `buf/buffer.h`, твой. Идея: буфер — это байты, а как их
интерпретировать, описывает отдельное число.

```
+----------+----------+------------+------------+-------+
|  cols    |  rows    |   strx     |   stry     | unit  |
|   15     |   15     |    15      |    15      |  4    |
+----------+----------+------------+------------+-------+
63      49 48      34 33        19 18         4 3     0
```

- `unit` — сколько байт в одном элементе (для RGBA — 4);
- `cols`, `rows` — сколько элементов по горизонтали и вертикали;
- `strx`, `stry` — сколько байт от элемента до следующего и от строки до
  следующей.

Пара `strx`/`stry` — это то, что делает конструкцию не просто структурой с
размерами. Меняя шаг, можно из одного и того же массива байтов сделать
подокно, перевёрнутую копию или один цветовой канал, ничего не копируя.

Для рендера важно только:

```c
	if (!bufGeomIsPacked(geo)) {
		fprintf(stderr, "gfx: texture rows are not packed\n");
		return 0;
	}
	if (BUF_UNIT(geo) == 4)
		format = GL_RGBA;
```

«Упакована» значит «строки идут подряд без промежутков». Видеокарте можно
отдать только такое.

**Ограничение, о котором надо помнить.** Шаг строки — 15 знаковых бит, то
есть не больше 16383 байт. При четырёх байтах на пиксель это текстура
шириной максимум 4095. Для текстур эпохи PS2 (256, 512) вопрос не стоит, но
`tga_Geo` для картинки 4096×4096 вернёт ноль. Лечится изменением раскладки
битов в `buffer.h`.

## TGA

Формат выбран потому, что он тривиален: заголовок 18 байт и пиксели.
Никакого сжатия, кроме простейшего RLE, никаких таблиц Хаффмана.

```c
	h = (const unsigned char *)datav;
	w = tga_Width(datav);        /* h[12] | h[13] << 8 */
	type = h[2];
	depth = h[16];
	top_down = (h[17] & 0x20) != 0;
```

Числа читаются побайтово, а не приведением указателя к `short *`. Две
причины: файл может лежать по невыровненному адресу, и порядок байт в
файле (little-endian) не обязан совпадать с порядком процессора.

Три вещи, специфичные именно для TGA:

**Порядок каналов.** В файле байты идут B, G, R, а нам нужно R, G, B:

```c
	put(dst, w, h_pix, top_down, i, p[2], p[1], p[0],
	    bytes == 4 ? p[3] : 255);
```

Аргументы `p[2], p[1], p[0]` — это и есть разворот. Если 24-битный файл, то
альфы нет и подставляется 255 (непрозрачно).

**Начало координат.** Бит 5 в байте 17 говорит, откуда идут строки: сверху
или снизу. Половина программ пишет так, половина иначе.

```c
static void
put(unsigned char *dst, int w, int h, int top_down, long i,
    int r, int g, int b, int a)
{
	x = i % w;
	y = i / w;
	if (!top_down)
		y = h - 1 - y;
	p = dst + (y * (long)w + x) * 4;
```

Вместо того чтобы распаковать и потом перевернуть вторым проходом, номер
пикселя сразу превращается в координаты, и при необходимости строка
отражается. Один проход.

**RLE.** Тип 10 сжат пакетами: байт-заголовок, затем либо один пиксель для
повторения, либо серия разных.

```c
		header = *p++;
		count = (header & 0x7F) + 1;

		if (header & 0x80) {
			/* повторить один пиксель count раз */
		} else {
			/* count разных пикселей подряд */
		}
```

Старший бит различает пакеты, младшие семь — длину минус один (нулевой
длины не бывает, поэтому единица не тратится впустую).

Проверки границ стоят на каждом шаге:

```c
		if (i + count > pixels)
			return -1;
		if (end - p < bytes)
			return -1;
```

Это загрузчик, а значит он читает данные, которым нельзя доверять:
скачанный мод, испорченный диск, специально собранный файл. Каждый разбор
здесь написан с расчётом на враждебный вход.

## OBJ

Текстовый формат Wavefront:

```
v -1.5 0.0 25.0        вершина
vt 0.5 1.0             координата текстуры
vn 0.0 1.0 0.0         нормаль
usemtl stone           дальше идёт материал stone
f 1/1/1 2/2/2 3/3/3    грань из трёх углов
```

Угол грани ссылается тремя независимыми номерами: позиция, координата
текстуры, нормаль. Это удобно художнику и неудобно видеокарте, которая
хочет один массив вершин, где всё уже сведено вместе.

### Свой разбор чисел

```c
static int
parse_float(struct parser *s, float *out)
```

Тридцать строк вместо `strtod`. Причина одна и она серьёзная: `strtod`
читает десятичный разделитель из локали. На машине с `ru_RU` строка `"1.5"`
превратится в `1.0`, потому что разделителем там считается запятая. Модель
схлопнется в точку, ошибки не будет, причину искать замучаешься.

Заодно разбор получается устойчивым к мусору и не требует нуль-терминатора,
а значит работает прямо по `mmap`.

### Два прохода

Первый проход только считает:

```c
	count_pass(data, len, &nv, &nt, &nn, &ntri);
```

Сколько вершин, координат, нормалей, треугольников. Зная точные числа,
можно выделить память один раз и не расширять массивы по дороге. Разбор
текста быстрый, второй проход по нему дешевле, чем перевыделения.

Треугольники считаются с учётом того, что грань может быть многоугольником:
`corners - 2` треугольника на грань, потому что она режется веером.

### Дедупликация

```c
static int
intern(struct build *b, const int key[3])
{
	slot = hash_triple(key[0], key[1], key[2]) & b->mask;
	while (b->table[slot] != 0) {
		at = b->table[slot] - 1;
		if (b->keys[slot * 3 + 0] == key[0] && ...)
			return at;
		slot = (slot + 1) & b->mask;
	}
	...
}
```

Хеш-таблица с открытой адресацией: если ячейка занята чужим ключом, идём в
следующую. Размер — степень двойки, поэтому взятие остатка заменяется на
`& mask`.

Ключ — тройка `(v, vt, vn)`. Одинаковые тройки дают одну вершину, разные —
разные, даже если позиция совпадает. Так и должно быть: на шве текстуры у
одной точки две разные координаты, и разделить её обязательно.

Хеш — FNV-1a, три умножения и три исключающих или. Не криптостойкий,
быстрый, для этой задачи достаточный.

### Таблица источников

```c
	b->m->source[at] = key[0];
```

Каждая вершина запоминает, из какой строки `v` файла она получилась. Это то,
что связывает модель с анимацией: кадры `.van` индексируются исходным
списком вершин, а не результатом дедупликации, который зависит от порядка
граней и от версии парсера.

### Переворот V

```c
			if (b->uv != 0)
				b->uv[b->nt * 2 + 1] = 1.0f -
				    b->uv[b->nt * 2 + 1];
```

В `.obj` ноль по вертикали внизу, в текстуре видеокарты — наверху.
Переворот делается один раз при загрузке. Если бы его не было, каждая
текстура была бы отражена, и это заметили бы только по буквам на стенах.

### Нормали, которых нет

```c
	if (nn == 0)
		smooth_normals(out);
```

Если в файле не было ни одной `vn`, они считаются: для каждого треугольника
берётся векторное произведение двух рёбер, результат прибавляется всем трём
его вершинам, в конце всё нормализуется. Вершина, которую делят несколько
граней, получает усреднённую нормаль — то, что нужно для плавного
затенения.

### Ограничение в 65535 вершин

```c
	at = b->m->nverts;
	if (at >= 65535)
		return -1;
```

Индексы 16-битные. Больше — ошибка, а не молчаливое переполнение, потому
что переполнение здесь дало бы модель, случайно перемешанную сама с собой,
и искать причину пришлось бы глазами.

## WAV

Файл из блоков: четырёхбуквенное имя, длина, содержимое.

```c
	while (p + 8 <= end) {
		chunk = u32at(p + 4);

		if (tag_is(p, "fmt ") && chunk >= 16) {
			format = u16at(p + 8);
			channels = u16at(p + 10);
			rate = (int)u32at(p + 12);
			bits = u16at(p + 22);
		} else if (tag_is(p, "data")) {
			pcm = p + 8;
			pcm_bytes = chunk;
		}
		p += 8 + chunk;
		if (chunk % 2 != 0)
			p++;
	}
```

Блоки перебираются в цикле, а не читаются по фиксированным смещениям:
между `fmt ` и `data` может лежать что угодно (метаданные редактора,
комментарии), и программа, читающая по смещению 44, ломается на первом же
файле из Audacity.

Последние две строки — выравнивание: блок нечётной длины дополняется одним
байтом, который в длину не входит.

**PCM** — несжатый звук: просто последовательность мгновенных значений
громкости. 44100 таких значений в секунду на канал.

Главное место:

```c
	if (bits == 16) {
		out->pcm = (const short *)(const void *)pcm;
		out->frames = pcm_bytes / (2 * channels);
		return 0;
	}
```

16-битный файл не копируется вообще. Сэмплы в нём уже лежат ровно так, как
их хочет микшер, и `wav_Parse` просто показывает внутрь твоих байтов. Это и
есть «не копировать, если можно не копировать» из твоей концепции buf.

Следствие, о котором надо помнить: буфер с файлом должен жить, пока звук
играет. Откатишь арену — микшер прочитает мусор.

8-битный вариант скопировать приходится, потому что там числа без знака в
диапазоне 0..255 и их надо перевести в знаковые:

```c
			wide[i] = (short)(((int)pcm[i] - 128) * 256);
```

## VAN

Свой формат вершинной анимации. 24 байта заголовка и кадры подряд.

```
0   "VAN1"
4   int   nverts
8   int   nframes
12  int   fps
16  int   flags        1 = в кадрах есть нормали
20  int   reserved
24  float frames[nframes][nverts][3 или 6]
```

Разбор — проверка сигнатуры и одна проверка размера:

```c
	need = 24 + (long)out->nframes * (long)out->nverts *
	    (long)out->stride * 4;
	if (need > len)
		return -1;

	out->frames = (const float *)(const void *)(p + 24);
```

Как и в WAV, данные не копируются: указатель внутрь файла.

Воспроизведение:

```c
	position = seconds * (float)a->fps;
	frame_a = (int)position;
	t = position - (float)frame_a;
```

Время в секундах превращается в дробный номер кадра. Целая часть — какой
кадр, дробная — насколько мы прошли к следующему.

```c
	if (loop) {
		frame_a = frame_a % a->nframes;
		if (frame_a < 0)
			frame_a += a->nframes;
		frame_b = (frame_a + 1) % a->nframes;
	}
```

При зацикливании номер берётся по модулю. Проверка на отрицательное нужна,
потому что `%` в C для отрицательных даёт отрицательное.

```c
	for (i = 0; i < nverts; i++) {
		from = source != 0 ? source[i] : i;
		if (from < 0 || from >= a->nverts)
			continue;
		pa = a->frames + off_a + (long)from * a->stride;
		pb = a->frames + off_b + (long)from * a->stride;

		dst[i].x = pa[0] + (pb[0] - pa[0]) * t;
		...
	}
```

Здесь работает таблица источников: i-я вершина модели берёт свою позицию
из `source[i]`-й вершины анимации. Формула `a + (b - a) * t` — линейная
интерполяция, самая частая формула в графике.

Координаты текстуры не трогаются: они не меняются от кадра к кадру, а
писать в них лишний раз незачем. Поэтому сэмплировать можно прямо в тот
массив вершин, что вернул `obj_Parse`:

```c
	anim_Sample(&walk, t, 1, mesh.verts, mesh.nverts, mesh.source);
	gfx_UpdateMesh(handle, mesh.verts, mesh.nverts);
```

Цена формата — память: `nverts * nframes * 24` байт. Пять тысяч вершин на
тридцать кадров — 3.4 МБ на одну анимацию. Резать надо частоту кадров, а не
модель: интерполяция вытянет и десять кадров в секунду.
