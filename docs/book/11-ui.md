# 11. Интерфейс и катсцены

Каталог `ui/`. Два независимых модуля: `gui.c` рисует меню, `cut.c`
проигрывает ролики.

## Два способа делать интерфейс

**Удерживаемый (retained).** Кнопка — объект. Ты создаёшь его, задаёшь
текст, вешаешь обработчик, кладёшь в дерево виджетов. Библиотека хранит
дерево, рассылает события, перерисовывает изменившееся. Так устроены Qt,
GTK, HTML.

**Немедленный (immediate).** Кнопки не существует. Есть функция, которую ты
зовёшь каждый кадр, и она возвращает, нажали ли на неё.

```c
	if (gui_Button(20, 20, 160, 32, "NEW GAME"))
		start_game();
```

Второй способ выигрывает именно в играх, и вот почему.

Меню игры — это отражение состояния игры. Кнопка «Продолжить» должна быть
только если есть сохранение, кнопка «Выход из машины» — только если ты в
машине. В удерживаемом подходе это означает создание и уничтожение
виджетов, синхронизацию дерева с состоянием и весь класс ошибок «на экране
кнопка, которой уже не должно быть». В немедленном это просто `if`:

```c
	if (g->has_save && gui_Button(20, 60, 160, 32, "CONTINUE"))
		load_save();
```

Кнопки нет — она не рисуется. Условие ложно — её не существует. Дерева нет,
рассинхронизации нет.

Плата: интерфейс перерисовывается целиком каждый кадр. Для игры, которая и
так рисует шестьдесят кадров в секунду, это ничего не стоит.

## Как кнопка помнит нажатие

Состояния в модуле ровно три переменные:

```c
static int active;         /* на каком виджете нажали кнопку мыши */
static int widget;         /* счётчик виджетов в этом кадре */
static int mouse_down;
static int mouse_was_down;
```

```c
int
gui_Button(float x, float y, float w, float h, const char *label)
{
	widget++;
	id = widget;
	over = gui_MouseIn(x, y, w, h);
	clicked = 0;

	if (over && mouse_down && !mouse_was_down)
		active = id;
	if (active == id && over && !mouse_down && mouse_was_down)
		clicked = 1;
	...
}
```

Идентичность виджета — порядковый номер вызова в кадре. Первая кнопка — 1,
вторая — 2. Пока порядок вызовов один и тот же от кадра к кадру, номера
стабильны.

Логика нажатия:

- кнопка мыши пошла вниз над виджетом → он становится активным;
- кнопка пошла вверх над тем же виджетом, который активен → это клик.

Так нажатие срабатывает по отпусканию, и можно передумать: нажал, отвёл
курсор, отпустил — клика не было. Ровно так ведут себя кнопки во всех
системах, и пользователь этого ждёт.

```c
void
gui_End(void)
{
	if (!mouse_down)
		active = 0;
	gfx_End2D();
}
```

Отпустили мышь — активного виджета больше нет.

Известная слабость подхода: если в середине списка появится новая кнопка,
номера сдвинутся, и в этот один кадр активной окажется соседняя. Заметить
это невозможно, но знать стоит; в больших библиотеках вроде Dear ImGui
идентификатор считается по хешу строки и позиции в стеке.

## Текст

```c
void
gui_Text(float x, float y, float scale, const char *text)
{
	cw = 1.0f / 16.0f;
	ch = 1.0f / 6.0f;

	for (i = 0; text[i] != 0; i++) {
		c = (unsigned char)text[i];
		if (c < 32 || c > 127)
			c = '?';
		c -= 32;
		col = c % 16;
		row = c / 16;
		u0 = (float)col * cw;
		v0 = (float)row * ch;
		gfx_Quad(x + i * font_w * scale, y, font_w * scale,
		    font_h * scale, font_tex, u0, v0, u0 + cw, v0 + ch, colour);
	}
}
```

**Атлас** — одна текстура, в которой нарисованы все буквы сеткой 16 на 6:
96 символов, от пробела (32) до `~` (127). Код символа минус 32 даёт номер
ячейки, номер ячейки даёт строку и столбец, столбец и строка дают
координаты текстуры.

Один прямоугольник на букву. Для строки из тридцати символов это тридцать
вызовов отрисовки — расточительно, но для HUD и меню незаметно. Правильное
решение — собрать всю строку в один буфер вершин и нарисовать одним
вызовом; понадобится, когда на экране будут субтитры и десяток счётчиков.

Атлас делается один раз скриптом:

```sh
python3 tools/mkfont.py /usr/share/consolefonts/Lat15-Terminus16.psf.gz font.tga
```

Скрипт читает консольный шрифт Linux (формат PSF — заголовок и битовые
карты, ничего сложного) и раскладывает символы сеткой. Подойдёт и любая
картинка, нарисованная руками: движок только режет её на клетки.

Без установленного атласа `gui_Text` тихо не рисует ничего. Это стоит
помнить, когда текст не появляется.

## Ползунок

```c
	if (active == id && mouse_down && input != 0 && w > 1.0f) {
		t = ((float)input->mouse_x - x) / w;
		t = m3_clampf(t, 0.0f, 1.0f);
		if (t != *value) {
			*value = t;
			changed = 1;
		}
	}
```

Значение передаётся указателем: виджет и читает его, и пишет. В
немедленном интерфейсе это естественно — состояние живёт у игры, а не у
виджета.

## Катсцены

`ui/cut.c`. Ролик — это список событий на часах.

```c
struct cutscene {
	struct cut_key key[CUT_MAX_KEYS];        /* положения камеры */
	struct cut_mark mark[CUT_MAX_MARKS];     /* события */
	struct cut_subtitle subtitle[CUT_MAX_MARKS];
	float clock;
	float length;
	float fade_in;
	float fade_out;
	int playing;
};
```

Собирается вызовами:

```c
	cut_Clear(&scene);
	cut_Camera(&scene, 0.0f, v3(0, 2, 10), v3(0, 1, 0));
	cut_Camera(&scene, 4.0f, v3(6, 3, 2), v3(0, 1, 0));
	cut_Subtitle(&scene, 0.5f, 3.5f, "MOST VZYAT NA RASSVETE");
	cut_Mark(&scene, 4.0f, EVENT_DOOR);
	cut_Fades(&scene, 1.0f, 1.0f);
	cut_Start(&scene);
```

### Камера

```c
	a = 0;
	for (i = 0; i < c->nkeys; i++) {
		if (c->key[i].at <= c->clock)
			a = i;
	}
	b = a + 1 < c->nkeys ? a + 1 : a;

	t = (c->clock - c->key[a].at) / (c->key[b].at - c->key[a].at);
	t = t * t * (3.0f - 2.0f * t);
```

Находим два ключа вокруг текущего времени и смешиваем. Последняя строка —
сглаживание (smoothstep): функция, которая на концах отрезка имеет нулевую
производную. Без неё камера трогается и останавливается рывком, потому что
скорость меняется скачком.

Сплайн через все ключи дал бы гладкость и на стыках между парами. Это
следующий шаг, если ролики станут длинными.

### События

```c
int
cut_Poll(struct cutscene *c)
{
	for (i = 0; i < c->nmarks; i++) {
		if (!c->mark[i].fired && c->clock >= c->mark[i].at) {
			c->mark[i].fired = 1;
			return c->mark[i].event;
		}
	}
	return -1;
}
```

Метка — просто число. Что оно значит, движок не знает и знать не должен:

```c
	while ((event = cut_Poll(&g->scene)) >= 0)
		handle_event(g, event);
```

Это граница между движком и игрой в чистом виде. Движок двигает часы и
говорит «настал момент 7». Что такое момент 7 — открылась дверь, взорвался
мост, началась перестрелка — решает игра. Именно поэтому здесь нет
скриптового языка: он понадобился бы, только если бы движок пытался понять
смысл событий.

Флаг `fired` гарантирует, что событие сработает один раз, даже если кадр
был длинный и часы перескочили через него.

### Затемнение и субтитры

```c
float
cut_Fade(const struct cutscene *c)
{
	if (c->fade_in > 0.0f && c->clock < c->fade_in)
		return 1.0f - c->clock / c->fade_in;
	if (c->fade_out > 0.0f) {
		left = c->length - c->clock;
		if (left < c->fade_out)
			return 1.0f - left / c->fade_out;
	}
	return 0.0f;
}
```

Возвращает непрозрачность чёрного: 1 в начале, 0 в середине, 1 в конце.
Рисует его игра, потому что только она знает, что должно быть поверх, а что
под:

```c
	float black[4] = { 0.0f, 0.0f, 0.0f, cut_Fade(&g->scene) };
	gfx_Quad(0, 0, app_Width(), app_Height(), 0, 0, 0, 1, 1, black);

	const char *line = cut_Text(&g->scene);
	if (line != 0)
		gui_Text(x, app_Height() - 60.0f, 2.0f, line);
```

Модуль катсцен не зовёт ни одной функции рисования. Он считает числа. Это
то же разделение, что везде в движке: кто считает, тот не рисует.
