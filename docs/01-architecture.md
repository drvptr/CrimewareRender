# 1. Архитектура

## Слои

Стрелка — «включает заголовок». Обратных стрелок нет ни одной.

```
        demo/main.c   (игра: логика, ИИ, уровни, меню — твоё)
             |
   +---------+---------+---------+---------+
   |         |         |         |         |
 core/app  world/    asset/     ui/      snd/
   |         |         |         |         |
   +----+----+---------+----+----+---------+
        |                   |
      plat/               gfx/           core/m3, core/arena, buf/
   (окно, ввод,     (треугольники)
    время, звук)
```

`gfx/gfx.h` не знает про GL. `plat/plat.h` не знает про X11. `asset/` не
знает, откуда взялись байты. `world/` не знает, чем рисуют. Это не
эстетика: это то, что позволяет собрать `PLAT=null GFX=null` и прогнать
всю игровую логику в CI без дисплея — что и делает `make check`.

## Монолит

Ты сформулировал это как «нет разделения на ресурсы и движок». В коде это
значит:

- нет скриптового языка, интерпретатора и байткода;
- нет формата уровня — уровень собирается вызовами `wld_AddSector()` из
  твоего C-кода или загружается из .obj, как ты решишь;
- нет системы сущностей — `struct game` в `demo/main.c` это и есть модель
  мира, и она твоя;
- нет системы событий поверх колбэков — есть три функции: `init`, `step`,
  `draw`.

Плата за это честная: игру нельзя изменить, не пересобрав её. Для игры,
которую пишет один человек, это не цена, а свойство — нет второго языка,
второго рантайма и второго набора ошибок.

## Память

`core/arena.c` — bump-аллокатор. Ты даёшь блок, движок отрезает от него по
порядку и никогда не освобождает по кусочкам.

```c
static char pool[48 * 1024 * 1024];
struct arena mem;
arena_Init(&mem, pool, sizeof pool);

long mark = arena_Mark(&mem);
load_level(&mem);          /* сотни аллокаций */
arena_Reset(&mem, mark);   /* уровень исчез, одна инструкция */
```

Почему не malloc: уровень живёт целиком и умирает целиком. Список свободных
блоков здесь не покупает ничего и стоит фрагментации. Плюс это ровно то, что
делает движок пригодным для freestanding-сборки — во всём движке нет ни
одного вызова libc, который нельзя убрать.

`obj_Parse()` — пример того, как это используется всерьёз. Он выделяет
массив индексов точного размера, массив вершин по верхней границе и
временные таблицы сверху; после разбора один `arena_Reset()` выбрасывает и
временные таблицы, и неиспользованный хвост массива вершин. Ноль потерь без
единого `free()`.

## Главный цикл

`core/app.c`, фиксированный шаг с накоплением:

```
пока живём:
    опросить ввод
    пока накопилось >= 1/60:  step(1/60);  накопилось -= 1/60
    draw(накопилось / (1/60))
    подать звук
    поспать, если успели
```

Симуляция идёт фиксированным шагом, отрисовка — с любой частотой. Это не
украшение: с переменным `dt` коллизии перестают быть воспроизводимыми, а
физика прыжка зависит от FPS. Догон ограничен пятью шагами — иначе один
затык (брейкпоинт, своп) заставляет цикл симулировать пропущенные секунды
дольше, чем они длились, и он уже не выберется.

## Что делать с epoll

Ты спрашивал, уместен ли он. В этом цикле — нет, и причина стоит того,
чтобы её записать: `epoll` отвечает на вопрос «какой из моих дескрипторов
готов» и блокируется, пока не готов никто. Игровой цикл обязан работать,
когда не готов **никто** — мир движется, пока игрок стоит. X11 даёт сокет,
который можно скормить epoll, но таймер на 16 мс всё равно нужен, и тогда
epoll не делает ничего сверх того, что уже делает неблокирующий `XPending()`,
зато привязывает тебя к Linux.

Он окупается ровно в один момент: когда появится сеть. Тогда правильная
форма — `epoll_wait()` с таймаутом, равным остатку кадра, и меняется одна
функция в `plat/`, а не архитектура.

## Где именно живёт непортируемое

| что | файл | как |
|---|---|---|
| окно, ввод | `plat/plat_x11.c` | Xlib напрямую |
| контекст GL | `plat/plat_x11.c` | GLX через `dlopen("libGL.so.1")` |
| звук | `plat/plat_x11.c` | ALSA через `dlopen("libasound.so.2")` |
| точки входа GL | `gfx/gfx_gl.c` | `plat_GlProc()`, ~45 указателей |

GLX и ALSA объявлены руками, потому что их прототипы не менялись двадцать
лет, а заголовки тянут за собой пакеты `-dev`. Итог: `ldd demo-bin` не
показывает ни GL, ни звука, и игра запускается там, где их нет — просто
молча и без картинки, если совсем плохо.

## Порядок вызовов за один кадр

```c
gfx_BeginFrame(r, g, b);
gfx_SetCamera(view, proj);
       int n = wld_Visible(&world, здесь, viewproj, список, 16);
       для каждого видимого сектора: gfx_DrawMesh(...)
       gfx_DrawMesh(модель), gfx_DrawSprite(эффекты)

       gui_Rect / gui_Text / gui_Button

```

`gfx_EndFrame()` и `plat_Swap()` зовёт сам `app_Run()`.
